---
description: Update documentation after a change
---

Update documentation so it describes the repository as it is (facts, not aspirations):

- `PROJECT_STATUS.md` and `CHANGELOG.md`;
- the technical docs whose behavior or contracts changed;
- `docs/OPEN_QUESTIONS.md` when a question is raised or resolved;
- an ADR in `docs/adr/` when a product or architecture rule changes (see `CONTRIBUTING.md`).

Edit docs deliberately and minimally. Do not bulk-reformat them (Prettier ignores Markdown on purpose).
